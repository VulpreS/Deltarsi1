## Вопрос

Можно ли вместо покупки опции API Trading торговать через автоматизацию браузерного терминала (Python + Playwright), чтобы избежать правила максимального прибыльного дня <30% при переходе между этапами? Как сильно это ускорит модельную проходимость?

## Подтверждённые официальные правила

- [API Trading Upscale](https://docs.upscale.trade/ru/kak-rabotaet-upscale/torgovlya-cherez-api): 30%-consistency и 60-секундная корректировка прибыли привязаны к **факту подключения API-опции к СЧЁТУ**, а НЕ к способу исполнения конкретного ордера. Если опция API уже активирована, **даже ручное открытие в терминале не снимает 30%**, а отключить опцию нельзя. API включается на Basic от $10000 (на $5000 недоступна).
- [Правила челленджа и торговли](https://docs.upscale.trade/how-to-join-upscale/participation_requirements): Basic без API не имеет 30%-gate на этапах, Basic с API имеет gate при переходе каждой фазы; Turbo — 30% только при выплате.
- [Официальный FAQ](https://upscale.trade/faq): программная торговля официально разрешена при наличии опции API Trading, про браузерную автоматизацию обычного Basic без API **прямого разрешения нет**.
- [Условия использования Upscale, обновление 15.05.2026](https://app.upscale.trade/terms-of-use-upscale.pdf): ограничения на попытки обходить ограничения платформы, использование ПО для нечестного преимущества и возможность не засчитать результат/закрыть доступ при выявлении запрещённых способов торговли. **Вывод о запрете любого Playwright-браузера прямо не написан**, но использовать браузер именно для обхода API-регламента рискованно; никакого заверения о разрешённости автоматической UI-торговли нет.

**Разделять способы:**
1. АВТОМАТИЧЕСКИЙ интерфейсный робот (Python нажимает «Открыть/Закрыть» от собственного процесса) технически реализуем, но НЕ ДОКАЗАНО, что Upscale квалифицирует это как ручную торговлю без API или разрешает обход правил; практическая безопасность/приём выплат сомнительна без письменного подтверждения.
2. **Сигнальный бот без доступа к торговому аккаунту**: анализ по закрытым 4h, Telegram-уведомление с символом, направлением, размером, защитой и сроком; **сам пользователь вручную подтверждает сделку** в терминале обычного Basic без API. Это гораздо более защищённый с точки зрения правил вариант; не устраняет риск ошибочного человеческого ввода и пропуска срочного выхода, поэтому серверные SL/TP сразу при входе.
3. ОФИЦИАЛЬНЫЙ бот по API: полная автоматизация, но дополнительное правило 30% применяется на счёт.

Не рекомендовать обход через имитацию человека, обход CAPTCHA, подмену user-agent, stealth Playwright, reverse-engineer private endpoints или сетевые вызовы вместо официального API — это не устанавливает разрешённость и создаёт риск аннулирования выплат.

## Контрольный эксперимент на ОДИНАКОВОЙ исходной сумме $10000

Изначальное прежнее сравнение $5000 Basic/noAPI против $10000 Basic/API имело лишнее отличие номинала; здесь оно устранено. На одном $10000 формально меняется **только account.api True/False**.

- Год **Jul2025–Jun2026**, дополнительный новый $10000 **Apr–Jun2026**.
- BTC ETH TON BNB XRP LINK, исключить ICP/ZEC; отдельный файл сравнения плюс общий engine из `experiments/portfolio_six_no_icp_zec_20pct/compare_add_second_signal.py`.
- Исходный сигнал `pine_events` от полностью закрытой 4h, ATR prior; исходные SL/TP каждой монеты и TON trailing по закрытой 1h, максимум 48h, без изменения «Новые инструкции».
- Вход **20% начального $10000 номиналом = $2000**, максимум 3 слота ($6000), если приходил второй сигнал на убытке — разрешён один дополнительный слот $2000, пока занято ≤2. Выведены две группы: контроль без добора и основной 20%+20% на убытке.
- Basic комиссия 0,008%/сторона, funding 0,015%/8h, статичный proxy spread 0,02% roundtrip; 5m свечи Binance USD-M. Дневной лимит 5%, общий лимит 10%, цели +5%/3д и +8%/5д, по cash realised profit; для API 30% gate на фазах и потенциальная корректировка выигрышей <60с (в 5m моделировании таких ноль).
- **Примечание:** это не историческое исполнение Playwright-бота, а математическая модель ручной торговли на обычном Basic без API с нулевой задержкой человека. Ручная торговля может пропускать позиции, менять fills и время закрытия.

## Надёжность браузерной автоматизации

- Веб-интерфейс работает с динамическими элементами, сессией/2FA, перерендериванием и сетью; кнопочный робот может совершить двойной ордер, пропустить стоп, забыть перевыставить TP, не узнать fill или запоздать с 48h таймером. У биржевого API структурированные состояния и подтверждения ордеров надёжнее.
- Готовая Python+Playwright схема работает в теории, но **полностью автоматическое управление счётом без разрешения Upscale для non-API аккаунта я НЕ РЕКОМЕНДУЮ**. Нужен короткий письменный ответ поддержки: «Разрешена ли автоматическая торговля через компьютерный браузер Playwright на Basic без опции API Trading? Будут ли операции считаться ручными для правил 30%/60с? Допустимы ли автозакрытия и SL/TP?»
- Если поддержка запрещает/не подтверждает, делать только сигнального помощника с ручным подтверждением приказов и серверными защитными ордерами, либо официальный API и соблюдение 30%.

## Ограничения финансовой модели

Те же, что у всех предыдущих экспериментов: `pine_events` исторически SMA21/RSI12/EMA7 и `pine_shade`, **не доказан 1:1 parity с подтверждённой пользовательской формулой RSI(27)−EMA7(RSI27)**. Все сделки по Binance 5m, не котировки и mark-price Upscale. Принудительное закрытие за 100 секунд до 48h не моделируется по секундам. Финансовые результаты in-sample по многократно исследованному году, не будущая доходность. Правила могут измениться. Случаев реальных торговых транзакций и выплат из бэктеста нет.
