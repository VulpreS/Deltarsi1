## Постановка

Входы **НЕ изменены**: строго `medium_red -> weak_red` для LONG и `medium_blue -> weak_blue` для SHORT по исполняемому корневому Pine `Delta`. Код в репозитории: `SMA(close,21) -> RSI(12,RMA) -> EMA(RSI,7) -> signed symmetric-log delta`. Не перепутать с неверными комментариями в Pine про RSI27 или желаемой альтернативной формулой RSI27−EMA7.

Для каждой позиции после закрытия **каждой 4h свечи** пересчитывается рыночный скоринг. Старший TF — предыдущий полностью завершённый UTC день. Исполнение на следующем 4h OPEN, внутри свечи стоп/тейк с консервативным `stop-first`. Начальный стоп = 2.5 ATR. Базовый тейк = 2.5 ATR и выход по противоположному цветовому сигналу. **Нет 48-часового ограничения удержания**. Трейлинг обновляется только после закрытия 4h.

8 отдельных рынков BTC, ETH, BNB, XRP, LINK, ICP, ZEC и TON (последний обрезан **до** делистинга 23.06.2026; нулевые свечи удалены). Данные взяты из уже существующих GitHub Release snapshots **без повторного скачивания трёх лет**.

Фиксированный номинал сделки $840, условный счёт $5000 **на каждую монету независимо**. Комиссии и спред: 0.18% за полный круг; стресс 0.36%. Это не торговля 5x на общем Upscale-счёте.

Хронология выбора:
- Калибровка: до 01.07.2025; проверка 01.07.2025–31.01.2026.
- Перевыбор/переобучение: до 01.02.2026; проверка 01.02–31.07.2026.
- Уже неоднократно просмотренный август–октябрь **не использовался** для обучения и выбора. Полностью независимого virgin OOS в старой истории больше нет.

## Эксперимент 2 — XGBoost принимает решение HOLD/EXIT внутри позиции

Обучаемые метки берутся из завершённых ДО обучения базовых сделок: на каждом баре спрашиваем, дал бы немедленный выход на следующем открытии результат лучше конечного выхода базовой стратегии минимум на **0.45 ATR**. Эта метка знает будущее ТОЛЬКО при построении ОБУЧАЮЩИХ примеров. Это **эвристическая proxy-метка**, а не оптимальная стратегия.

Для первого обучения ~4008 примеров решений (309 базовых сделок), для расширенного — ~6216 (477 сделок). Классификатор XGBoost (140 деревьев, глубина 3), с балансом на уровне сделок. Порог вероятности выбирался на соответствующем раннем обучающем периоде и оказался 0.55 для всех трёх вариантов. Тестовые сделки и будущие свечи не подмешивались в обучение.

Сравнение **трёх наборов признаков**, при одинаковых входах и жёстких защитных стопах:

| Признаки ML | Вал1 ML | Вал2 ML | Базовая Вал1 | Базовая Вал2 |
|---|---:|---:|---:|---:|
| Только DeltaRSI + PnL, возраст позиции, ATR | −0.280% | +0.951% | −0.151% | +3.134% |
| + оригинальный Pine REGIME score | −1.146% | +1.452% | −0.151% | +3.134% |
| + нормализованный старший score (исследовательский) | −1.632% | +1.538% | −0.151% | +3.134% |

На втором периоде ML сделал **75–84 преждевременных закрытий** из 134–135 закрытых сделок (56–62%); на первом — 134–139 из 179–180 (75–77%). Это указывает на ключевую проблему метки: XGBoost активно учится избегать потенциального позднего отрицательного движения, **но часто отсекает трендовые прибыли**. Итоговый `mean` хуже контроля во всех шести проверках.

В переносе XGBoost с нормализованным score, при исключении одной монеты из обучения, изменение относительно базового контроля за 02–07.2026:

- BNB +1.792 п.п.
- XRP +0.272 п.п.
- LINK −1.761 п.п.
- ICP +0.817 п.п.

## Что реально выяснилось

1. **Входы DeltaRSI пока выгоднее сохранять как отдельно проверяемый механизм**. Переносить жёсткие score-фильтры на все монеты нельзя.
2. **Объектив выхода важнее сложности модели.** Метка «сейчас лучше, чем конечный базовый выход» вызывает чрезмерную досрочную фиксацию; XGBoost не научился удерживать сильные тренды.
3. **Режим — недостаточно полная информация без состояния позиции:** уже набранной прибыли, текущего ATR, MFE/MAE, накопленной силы импульса и изменения дневного bias.
4. **Проблемные активы — ZEC, ICP, TON/GRAM**: разные фазовые реакции; TON после делистинга не соединять свечами с GRAM (новый контракт с 02.07.2026).
5. **Для следующей версии** нужна оценка `risk-adjusted hold value` для альтернатив HOLD/EXIT, в том числе с несколькими горизонтами будущих движений, и динамическое переключение между `TREND_RIDE` (не рубить выигрыш) и `PROFIT_PROTECTION`, вместо обычного бинарного regret-label. Метки и пороги подбирать только на ранней истории; новые данные после 01.11.2026 для подтверждения, не переписывать фrozen-live-эксперимент по результатам старого рынка.
6. **Не внедрять модели в Upscale или старые форвард-стратегии сейчас.** Красивая историческая кривая и успешный GitHub Actions не равны устойчивому финансовому преимуществу.
